# Working in this folder with other agents

Several agents (Claude Code sessions, Codex, people) edit this checkout at the same time. These rules exist
because on 5 September two agents rewrote the same README paragraphs within minutes of each other, one agent's
commits swept in another's half-finished edits, and a footnote landed inside a table. Keep them; they are short.

## 1. One writer per path

| path | owner while a campaign is running |
|---|---|
| `README.md`, `report/`, `box/` (chains, lists, eval scripts, `frontier.py`, `econ.py`, `mksummary.py`), `results/` | the benchmarking session (Claude Code) |
| `bench/`, `cells/`, `patches/`, `tests/`, `vast/`, `analysis/` | the harness/priority-work agent (Codex) |
| `AGENTS.md`, `CLAUDE.md` | Nish |

To change a file you do not own: do it on a branch and say so in the commit message, or ask Nish to reassign
the path. Do not edit it in the working tree on `main`.

## 2. Shared documents are edited, not rewritten

`README.md` and `report/*.html` are the deliverables, and both agents have things to say in them.

* Add your content as a new paragraph, row or footnote; never rewrite, reflow or renumber someone else's.
* Edit by exact string replacement of the text you are changing. Never regenerate a whole section from a
  template, and never reformat (line wrapping, table alignment, encoding, line endings — UTF-8, LF).
* Footnotes go in the footnote block under the table they belong to, never inside the table.
* If a number you want to change was written by the other owner, leave the number and add your correction as a
  new sentence with the evidence; the owner reconciles.

## 3. Commit only what you changed

* `git add <the files you edited>` — never `git add -A`, `git add .` or `git commit -a` on `main`.
* Before `git push`: `git pull --rebase`. Small commits, message says what changed and where.
* Never commit another agent's uncommitted working-tree changes. If `git status` shows files you did not touch,
  leave them alone.
* Bulk imports and experiments go on a branch (`priority-harness-import` is one); `main` must always build the
  README and report as they stand.

## 4. Derived files come from scripts

`results/summary_all.tsv`, `report/frontier.svg` and the economics tables are generated by `box/mksummary.py`,
`box/frontier.py` and `box/econ.py`. Never hand-edit them; regenerate and commit the script and its output
together. `results/` is append-only: pull scripts add files, nobody edits result JSON or logs.

## 5. Rented boxes

* The tmux session that runs a chain belongs to whoever started it. Never kill a tmux session you did not start;
  never run a pattern kill (`pkill -f`, `killall python`) on a box; use `box/hardkill.sh`'s `kill_all` only from
  your own chain.
* Never overwrite a script a box is executing (bash reads it by offset and dies mid-line). Copy to a temporary
  name and rename into place (`push.sh` does this).
* Before a new arm's throughput is reported anywhere, its 20-item tripwire (`quality20.py`) must be clean and,
  for a headline, its 403-item quality run must exist. The 1,300 tok/s GLM layout that failed with 0.643 had
  already failed its tripwire; nobody looked.

## 6. Secrets

No keys, tokens or passwords in the repository, in chat, or in a script argument. Key files live outside the
tree (`/workspace/.openrouter_key`, mode 600, on the box); local copies are deleted after transfer; scripts read
them into environment variables and never echo them.

## 7. Say what you are doing

When you take a path, start a long edit, or change a shared number, leave one line in `HANDOFF.md` (append-only:
time, agent, path, what). Read it before you start.
